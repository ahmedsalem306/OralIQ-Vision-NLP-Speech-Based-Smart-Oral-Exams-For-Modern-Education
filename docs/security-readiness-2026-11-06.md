# مراجعة الأمان وتجهيز الإنتاج — ٦ نوفمبر ٢٠٢٦

المراجعة تخص فرع `codex/contabo-production`. الموقع الأساسي ما زال يعمل بباك إند الاستضافة
السابقة؛ رفع كود الفرع لا يعني تحديث السيرفر القديم. لا يوجد سيرفر Contabo أو دومين API متاح
في الجلسة، ولا يمكن اعتماد سعة أو جاهزية تشغيلية نهائية قبل اختبارهما.

## الإصلاحات

| المشكلة | ما تغير |
| --- | --- |
| ربط محاضر بفريق بمجرد معرفة بريده | دعوة معلقة لمدة ٧ أيام؛ لا يتغير `owner_id` إلا بعد قبول صاحب الحساب المصادق عليه. رفض وإعادة استخدام الدعوة والصلاحية وسعة الفريق تتحقق من السيرفر. |
| تجاوز حد الطلب بإرسال chunked أو حجم معلن غير صحيح | حد فعلي لتدفق الطلب قبل قراءة multipart وتخزين الملفات المؤقتة، مع 413 عند التجاوز. |
| صورة صغيرة مضغوطة يمكن أن تنتج مصفوفة ضخمة | التحقق من نوع الصورة وأبعادها قبل OpenCV، بحد 4096 لكل ضلع و12 مليون بكسل. |
| فك صوت طويل بالكامل قبل حد Whisper | فك صوت محدود المدة لWhisper وResemblyzer وMFCC؛ تحويل ffmpeg بحد 600 ثانية وتنظيف الملف الجزئي. |
| ملفات قوائم تشغيل يمكن أن تطلب روابط أثناء فك الوسائط | تقييد بروتوكولات وصيغ PyAV وffmpeg إلى صيغ التسجيل المحلية، ورفض قوائم التشغيل الشبكية. |
| وجهة دفع تقبل نطاقًا ينتهي بحروف kashier.io فقط | قبول `kashier.io` أو نطاق فرعي حقيقي فقط، ورفض بيانات الدخول في الرابط. |
| إمكانية خلط توكن سؤال قديم بامتحان جديد | حل التوكن إلى الامتحان الأصلي والتحقق من ملكيته قبل إضافة السؤال؛ رفض المجموعات غير الموجودة. |
| JWT لا يشترط تاريخ انتهاء | اشتراط `exp` و`sub` عند التحقق، مع تثبيت الخوارزمية والتحقق من نسخة الجلسة. استبدال python-jose بـPyJWT. |
| PBKDF2 يستخدم كلفة افتراضية قديمة | رفع كلفة SHA-256 إلى 600 ألف تكرار للحسابات الجديدة، وترقية الهاش القديم بعد تسجيل دخول صحيح فقط، مع استمرار قبول كلمة المرور القديمة. |
| مسار تشخيص يعرض أسماء الإعدادات الناقصة على الإنتاج | `/health/keys` متاح في التطوير فقط. |
| إملاء صوتي متزامن متاح لكل حساب | قصره على المحاضرين، ومهمة واحدة دون طابور انتظار غير محدود في الـAPI. |
| طابور وتسجيلات محفوظة بدون سقف إجمالي | سقف افتراضي 500 مهمة قيد التنفيذ/الانتظار و2GB صوت محتفظ به، بما فيه الصوت الفاشل. القبول يسلسل بمعاملة PostgreSQL؛ الرفض لا يقبل إجابة بلا مهمة، وتكرار طلب سبق قبوله يظل صالحًا. |
| عملية التطبيق تعمل بصلاحيات root | مستخدم حاوية UID 10001، وإسقاط capabilities ومنع اكتساب صلاحيات جديدة. |

الدعوات الجديدة لا تمنح صلاحيات إدارة نتائج أو بيانات لم تكن متاحة سابقًا. العضويات القديمة
تحتاج مراجعة مع أصحاب الحسابات؛ لا نحذف ارتباطات قائمة تلقائيًا دون معرفة مصدرها.

## المكتبات والفحوص

- الفحص الكامل قبل الترقيات: 335 اختبار باك إند ناجح. بعد ترقيات الـAPI وإصلاحات الأمان: 344 اختبارًا ناجحًا في التشغيل الكامل، مع اختبارات إضافية ناجحة لتقييد الوسائط وترقية كلمات المرور.
- اختبارات الإصلاحات والفوترة والصلاحيات والدفع: ناجحة في تشغيل منفصل.
- اختبارات الواجهة: 14 اختبارًا ناجحًا. تم إصلاح أمر تشغيل TypeScript على Node 22.
- اختبارات أداة النسخ الاحتياطي تعمل بأدوات PostgreSQL وGPG بديلة؛ تم إصلاح افتراض مسار المجلد المؤقت في اختبارها. لا تغني عن استرجاع قاعدة حقيقية على Linux.
- typecheck وlint وبناء Vite نجحت؛ توجد تحذيرات lint قديمة غير معطلة للبناء.
- npm audit لملف القفل المصحح: صفر تنبيهات معروفة وقت الفحص؛ هذا ليس ضمانًا لغياب الثغرات.
- فحص أنماط محددة للأسرار في الملفات المتتبعة: لم يعثر على تطابق. لا يغطي سجل Git كاملًا أو جميع أنواع الأسرار.
- بيئة Python المحلية القديمة: 220 تنبيهًا معروفًا في 28 حزمة، وليس 220 استغلالًا مثبتًا في التطبيق.
  هذه البيئة ليست صورة السيرفر الجديدة. تمت ترقية متطلبات API والنماذج، وإزالة الاعتمادات غير المستخدمة
  التي تعارض الإصدارات المصححة، واختيار Python 3.12 بدل 3.10.
- اختبارات الـAPI تعمل على FastAPI 0.162 / Starlette 1.10 / PyJWT 2.15.1 في بيئة معزولة.
  نماذج الاختبارات بدائل محلية؛ لا تثبت جودة أو أداء الاستدلال الحقيقي بعد ترقية مكتبات ML.
- أضيفت فحوص GitHub Actions للبناء والاختبارات وnpm audit وpip-audit وبناء صورة Linux وفحصها بـTrivy.
  حالة تنفيذها موثقة في GitHub؛ وجود ملف workflow وحده لا يعني نجاح تشغيله.
- اختبار PostgreSQL متزامن في CI ينشئ schema مؤقتًا منفصلًا ويمسحه، للتحقق أن سقف الطابور
  لا يمكن تجاوزه بطلبين متزامنين. يتخطى التشغيل المحلي عند عدم وجود `TEST_POSTGRES_URL`.
- المحاولة الأولى لحل اعتمادات النماذج توقفت بسبب مساحة القرص المؤقت؛ أُعيدت بكاش ومجلد مؤقت
  على D. حل الإصدارات محليًا لا يساوي نجاح صورة Linux أو تشغيل النماذج.

فحص قراءة فقط للاستضافة الحالية: صفحة السياسة 200، ومسارا `/docs` و`/debug` على الباك إند
أجابا 404، و`/api/v1/users/me` دون جلسة أجاب 401. `/health` لم يجب خلال مهلة 15 ثانية؛
هذا لا يحدد وحده هل السبب نوم الاستضافة أو عطلها. لم تُجرَ محاولات اختراق أو ضغط على بيانات حقيقية.

## شروط فتح التشغيل التجاري

1. نجاح بناء صورة Linux وفحص حزمها، ثم اختبار تسجيل فعلي مع Whisper وSBERT والوجه والصوت.
2. شراء السيرفر والدومين، وضبط SSH بالمفاتيح والتحديثات والجدار الناري؛ نشر PostgreSQL داخليًا دون منفذ عام.
3. نقل الداتا والتأكد من الأعداد والعينات، والمحافظة على مفتاح JWT ثابت؛ عدم وجود قاعدتين تستقبلان كتابة مستقلة.
4. SMTP فعال وتأكيد البريد، وبيانات Kashier الحقيقية وwebhook وCORS مطابقة للدومين، وتجربة دفع واسترداد حقيقية محدودة.
5. نسخة احتياطية مشفرة خارج السيرفر وتجربة استرجاع، وتنبيهات للأخطاء والمساحة وعمر طابور التصحيح.
6. قياس الضغط باستخدام تسجيلات عربية بطول الاستخدام المتوقع قبل بيع سعة متزامنة أو وعد بوقت ظهور النتيجة.

التحقق بالوجه الحالي لا يتضمن liveness: الصورة المعاد تشغيلها أو الكاميرا الافتراضية تظل مخاطرة.
تنبيهات المتصفح مؤشرات قابلة للتلاعب، ولا يصح اعتبارها وحدها إثبات غش. JWT في localStorage
يعني أن منع XSS والمحافظة على المكتبات الآمنة يظلان ضروريين. لا توجد شهادة بأن النظام خالٍ من الثغرات.
