opened exam/biometric routes and kept paid checkout paused independently.

**Accounts are open at https://oralliq.com. Exams, biometric enrollment and paid
checkout remain paused.** This enables account testing without describing the
whole exam service as fully launched.

## What is live

- `/api/v1/register`, password/Google sign-in, email verification/resend,
  `/users/me`, and plan/status reads reach the existing API. The proxy whitelist
  names exact account routes; other API operations still return 503 with the
  bilingual `EXAMS_PREPARING` message.
- `/srv/oraliq-web/accounts-maintenance` can close account routes independently.
  It is absent after the successful rollout. The original `api-maintenance`
  marker remains present. `/service-status.json` reports accounts available and
  exams unavailable; the UI explains this state.
- Google configuration is fetched from the server rather than a stale build
  fallback. Configuration unavailable during maintenance no longer launches an
  unusable Google flow or exposes server setup instructions to students.
- Contabo serves public HTML for `/`, `/privacy-policy` and `/refund-policy`.
  Each has a matching canonical URL; policies also have their own metadata.
  Sitemap contains those three pages. Account/exam URLs receive `noindex,
  nofollow` headers and the app shell. Missing assets and unknown routes return
  404. Old invisible FAQ structured data and its outdated concurrency claim
  were removed.

registration 202, unverified-login rejection, encrypted outbox/domain link,
verification/profile access, single-use verification tokens, password login and
wrong-password rejection, duplicate-signup ownership protection, admin-role
rejection, Google configuration, and zero mail delivery attempts. The test
database/container were removed; production test accounts were not created.

A separate check authenticated to the actual SMTP service over verified TLS
without MAIL FROM, RCPT TO or DATA commands. It sent no message. A **20-table
pre-opening pg_dump** was verified. Checkpoint:
`/root/oraliq-accounts-seo-20261117-001022`.

On the public hostname, Google configuration and its CORS preflight now return
200. Empty registration/login/verification requests return expected validation
422 rather than proxy 503. Anonymous profile/billing-status reads return 401.
Exam, voice and checkout requests remain 503. Public HTML/canonical, private
noindex, robots/sitemap, social image and 404 checks passed. Reports are ignored
under `loadtest-artifacts/accounts-seo-20261117/`.
